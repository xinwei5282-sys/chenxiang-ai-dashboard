# 广垦沉香数据大屏 · 指标口径与样例核对

版本：v1.0 / 2026-09-09。本文为新增大屏模块的原型交付口径，供需求评审与正式接入使用；不修改旧版消费者端范围。产品、内容名称和数值均为演示样例，不代表真实经营结果。

## 1. 页面与验收范围

| 用户需求 | 已实现 |
| --- | --- |
| 数据指标模型 | 期末产品档案、扫码/NFC到达、PV、UV、问答、分享触发、热门问题及分享触发率 |
| 经营总览 | 5项主指标、每日趋势、来源占比、产品表、热门内容和问题榜 |
| 内容传播 | 数字生命卡、GEO页面、文化内容汇总及明细，类型筛选和指标排序 |

## 2. 统一时间、去重和关联口径

- 时区：`Asia/Shanghai`。日期筛选为 `[起始日00:00, 结束日次日00:00)`。UTC时间戳先转北京时间再分组。结束日的23:59:59包含在内。
- 主屏默认2026-08-11至2026-09-09，样例另提供2026-07-12起的前期数据，用于等长周期比较。顶部当前时钟不表示业务数据实时更新。
- 对比幅度：`(本期值－前期值) ÷ 前期值 × 100%`。前期为紧邻本期的等长天数；档案比较前后期末存量。零基数、不适用或事件历史不完整时显示“暂无可比数据”。
- 所有指标共用规范化事件源；先去除失败、机器人、测试事件，再按`event_id`去重。问题额外按`request_id`去重，归属于第一次成功事件，避免跨日重传重复计算。
- 产品/内容筛选相交生效。选择内容后，档案范围映射到该内容关联产品；同一产品不同页面对应同一档案存量。通用内容无产品关联，档案显示“不适用”。无效产品或内容返回空集。
- 匿名访客标识仅用于去重，不代表已认证自然人；跨设备可能重复识别，清除存储也可能产生新标识。原型没有个人身份和用户问题原文。
- 来源归因是每次页面PV的来源归类，不是用户级首触或末触归因。已识别来源互斥；无已知来源归为直接访问。

## 3. 指标字典

| 指标 | 业务口径 | 核对与边界 |
| --- | --- | --- |
| 产品档案数 | 筛选结束日期末已发布`archive_id`去重数，档案代表单品管理单元 | 不是产品款数或期间新增量；排除草稿；通用内容不适用。正式接入需按档案历史状态重建截止日快照 |
| 扫码/NFC访问 | 消费者成功到达入口页的有效`entry`事件数 | 等于NFC到达+扫码到达；硬件读卡、仅扫码未打开、失败和重传不计；不与PV相加 |
| 页面浏览量PV | 有效`pageview`事件数 | 页面加载完成后采集；重新有效访问可计新PV，同次上报重试不得更换事件ID；排除机器人、测试、失败 |
| 独立访客UV | 筛选范围有效PV中的匿名`visitor`去重数 | 无标识不计UV；不可将每日或每内容UV直接相加 |
| AI问答次数 | 成功完成回答的用户问题`request_id`去重数，包含每次有效追问 | 一次用户提问计一次，排除失败、缺请求ID、模型内部重试及多段流式输出 |
| 内容分享触发 | 用户调用分享或复制分享链接产生的有效`share`事件数 | 不代表发送成功、收件人数或送达；平台无法提供成功回执时不能标为分享成功 |
| 热门问题 | 预设规范`question_id`聚合成功问题，按次数降序 | 展示标准问题标题、类别和次数；同义问题归类需冻结分类规则，低置信匹配正式接入时归“其他” |
| 热门问题占比 | 某类成功问题次数÷全部成功问题次数 | TOP5只是部分排名，其占比不必合计100%；不展示用户原文 |
| 内容分享触发率 | 当前内容的分享触发次数÷PV×100% | PV为0时界面显示“—”；不是送达率、用户分享率或成交转化率 |

每条事件只归属一个内容。趋势的PV/入口/问答/分享之和与主指标相等；页面来源PV之和、所有内容的PV之和等于总PV。通用内容不归属任何产品，所以产品PV之和可以小于全部内容PV，不应强行补入某产品。

## 4. 内容传播与GEO边界

- 数字生命卡：产品身份页及其访问互动。
- GEO页面：已接入、可被服务端或前端观测的GEO内容页面。
- 文化内容：已接入的故事或知识内容。
- 载体类型和访问来源是两个独立维度：例如数字生命卡可来自扫码，也可来自分享回流。
- 搜索引擎曝光、关键词排名、AI答案提及/引用、外部渠道阅读量需另行授权接入对应数据源；没有接口时不估算为本屏指标。
- 已有只读知识页面未在此任务中增加分享按钮。正式采集能否获得原生分享触发取决于载体及平台接口能力；未接入时应标记未接入，不能把缺数据表现为零。

## 7. 后续真实接入的最小约定

建议事件公共字段：`event_id / occurred_at / event_type / anonymous_visitor_id / content_id / source / status / is_bot / is_test`；问答另含`request_id / question_id`；档案源含`archive_id / product_id / published_at / status_history`。

需业务方冻结：单品档案管理粒度、已发布状态及注销历史、成功到达与页面加载触发点、匿名访客期限、分享触发可采集性、问题分类词表、授权产品范围、数据延迟与补报规则。正式统计由后端完成并返回`as_of / coverage / freshness / definition_version`，浏览器不接收原始个人事件。

原型当前仅以确定性事件即时计算，不包含生产登录、埋点SDK、后台接口、实时推送及外部GEO平台接入。验收证据保存在`audit/browser-report.json`和页面截图中，计算测试由`npm test`执行。

## 8. 知识库建设与维护成果（2026-09-09补充）

根据本轮明确要求，大屏新增知识库展示：主屏首项为“已发布知识”，建设成果区域默认展示来源、期间维护、待审核和分类TOP4；原产品表通过“产品”切换保留。新增“知识库全景”供管理员、运营、展示访客查看聚合成果；访客仍不可导出、进入内容传播明细或校验样本页。此矩阵补充覆盖上文的旧访客边界。

### 8.1 指标口径

| 指标 | 口径 | 边界 |
| --- | --- | --- |
| 知识条目总量 | 截止日已创建knowledge_id去重数 | 包含已发布、待审核、草稿、停用四种互斥状态；不将版本或向量切片算作新条目 |
| 已发布知识 | 截止日最新状态为published的条目数 | 来源资料不是知识条目；未审核知识不能用于对外回答 |
| 关联来源资料 | 所选知识条目关联且截止日前已入库的source_id去重数 | 同一来源被多条知识引用只计一份；不是全部上传文件数 |
| 期间维护条目 | 起止日期间发生创建、提交、发布、发布修订或停用的knowledge_id去重数 | 同条目多次操作计一条；包含草稿维护，不能与公开动态列表直接比较行数 |
| 期间新增知识 | 在筛选期间创建的knowledge_id去重数 | 为期间维护条目的子集 |
| 待审核知识 | 截止日最新状态为pending的条目数 | 显示聚合数量，不公开候选原文、内部备注及审核人信息 |
| 检索命中率 | 成功问答中的命中检索请求数÷成功问答中的实际检索请求数 | 未调用检索不进入分母；无检索时为不适用；命中≠回答正确率 |
| 待完善问题 | 成功问答中的未命中检索按标准问题分类排序 | 展示标准题目，不能泄露用户原文；完整分类次数之和等于未命中次数 |

条目主分类遵循现有沉香方案的12类：产品系列、香型产地、年份、工艺、检测证书、品牌文化、活动权益、佩戴礼赠、养护、香文化生活、常见问题、表达边界。分类合计及状态合计都等于知识条目总量。

知识资产按关联产品筛选；页面筛选映射页面关联产品，通用页面映射通用知识。知识维护不是页面行为，所以不伪造页面级条目归属。问答检索表现继续按所选页面内问答统计，页面脚注明确两类范围。

## 9. 固定单屏展示（最新决策）

用户明确一屏同时展示，不需要切换。本节覆盖上文所有多页面及标签切换设计。数据口径不变，展示入口改为`screen.mjs`与`screen.css`。

屏幕以“8项核心指标 + 三列两层6个固定区域”组织：左列知识建设与近期维护，中列访问传播与产品触达，右列AI问题与内容排行。12类知识、四种发布状态、产品表、五种访问来源及生命卡/GEO/文化内容都同时显示。排行明确TOP5、近期动态明确最近4条，属于固定摘要，不进行自动轮播。

筛选、演示角色与汇总导出收进展示设置；口径与核对收进操作弹层。没有第二张展示页，也没有模块或趋势指标切换。展示访客无导出，运营/管理员可以导出聚合汇总；上述仅为原型权限演示。

1920×1080为设计基准，1440×900与4K整体等比缩放。不同宽高比保留边缘留白；不裁切、不滚动。不能以CSS隐藏溢出来证明适配成功，须验证画布边界完全位于视口内。
